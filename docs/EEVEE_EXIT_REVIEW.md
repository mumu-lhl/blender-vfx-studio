# 软件 Eevee 的退出崩溃检查

[#122](https://github.com/mumu-lhl/blender-vfx-studio/issues/122) 记录 Ubuntu 24.04 后台检查的退出问题。两次完整连段和一次重跑都渲染成功、通过 31/33 帧原生像素比较，随后 Blender 以 139 退出；没有据打印标记忽略进程失败。

临时 [PR #125](https://github.com/mumu-lhl/blender-vfx-studio/pull/125) 只生成真实的 31/33 两个诊断帧，反复运行原样的无插件检查，不将它们冒充完整序列。Actions 首次三次退出码为 -11、0、0，本地 Debian 三次均正常。已下载校验崩溃产物，栈经过 Mesa 25.2.8 的 libgallium 和 libEGL_mesa 清理路径，Python 栈为空。不能仅凭这条栈断言与场景内容完全无关。

第二轮分别检查旧刀光、检查后清空临时场景、单线程和关闭着色器缓存，每组三次均正常退出。这还不足以证明某项设置彻底修复了问题；第三轮 Actions 40306513193 的实际产物已下载校验：原样三次仍为 -11、0、0，主动清理十次全部为 0，原生像素断言均执行。

测试补丁在像素、尾段清空、原文件 SHA256 和检查记录全部确认后，用 read_factory_settings(use_empty=True) 释放临时场景，再让 Blender 正常退出。它只改变后台检查的收尾，不保存原文件，不改变生成器、不跳过断言，也不忽略退出码。本地该补丁三次正常退出；Actions 十次对照也正常，完整流程继续验证。

#123 已让失败任务保存原始帧、原生场景和崩溃文件七天。临时诊断分支不得合并进 main，其中跳过普通 CI 的配置仅用于快速定位；正式分支保留完整检查。这个记录不等于所有 Blender/Mesa 退出问题已解决。

正式补丁的功能提交 `0dcf717a082f4aabdc1091a23d6a38b35636a163` 已通过 [Actions 40306998982](https://github.com/mumu-lhl/blender-vfx-studio/actions/runs/40306998982) 全部五项 CI，包括完整 60 帧、原生重开、视频与离线打包。接入刀光和压力核的组合分支也已完成完整连段，保持正常进程退出。此处解决的是可复核的后台测试收尾，仍不承诺覆盖所有图形驱动的退出路径。
