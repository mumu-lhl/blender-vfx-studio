# ADR 0001：用 Blender 原生数据保存和播放效果

状态：已采纳。ADR 是架构决策记录，用来说明为什么选择某种实现，以及接受了哪些限制。

我们希望用户能直接编辑生成的网格和节点，多个效果互不干扰，并能把 `.blend` 交给没有安装插件的人播放。默认效果也需要能在没有独立显卡的机器上使用。

因此，参数放在 Empty 控制器的自定义属性中，效果保存为原生 Mesh、材质、节点组和动画。Blender 简单驱动表达式负责把参数连接到节点输入；Python 负责创建、复制、删除、显式采样和界面操作，不在每一帧遍历对象来播放效果。首个实现是冲击波和能量环，后续模块沿用同一做法。

每个实例使用独立节点组和网格，代价是增加内存。我们接受这项开销，因为复制后独立编辑更直接，也更容易避免误改其他实例。只有实际场景证明内存成为问题时，才考虑共享不可修改的资产。

驱动表达式必须属于 Blender 的简单表达式范围；用户手动删除被引用的节点输入或属性，也可能破坏效果。需要积累历史状态的模拟仍要单独处理缓存，不能直接套用当前效果的任意帧播放规则。目前不开发独立的 Unity VFX Graph 式编辑器。

Blender 5.2.2 后台测试，以及关闭脚本自动执行、未加载插件的新进程保存重开测试，验证了当前效果能依靠原生数据播放。视觉检查和尚未覆盖的平台见 [ROADMAP.md](../../ROADMAP.md)。
