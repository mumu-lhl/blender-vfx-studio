# Energy Charge：向内压缩的路径与能量团

[#99](https://github.com/mumu-lhl/blender-vfx-studio/issues/99) 继续处理用户指出的聚能感不足。它替代 PR #90 的封闭核心造型，仍在视觉迭代中；整体艺术目标 #89 保持开放，0.22.3 未发布。参考的实际观看范围和技术拆解见 [参考笔记](REFERENCE_VISUAL_STUDY.md)，不使用作品中的素材或源码。

## 从白色外壳改为有空隙的汇聚

对照 `15254ea` 的连续连段图，13–27 帧主要是一块白蓝壳。旧核心外表面的白色混合接近 0.95，横向仅收缩 32%，同时半径增长；高度基本不收缩。噪声、翻动和表面亮纹没有改变封闭轮廓，因此难以读出能量在向内挤压。

真实资产生成器 `tools/charge_design.py` 现在生成六条不同长度、宽度和弯曲高度的内卷路径，围绕一个小内核，路径之间保留真实空隙。45%–84% 的生命阶段中，路径横向收紧到 38%、高度收紧到 60%；截面另行保留厚度，让末段更密，而不是一起变成细线。主要亮色集中在到达中心的前端与小内核，外层保留青蓝和暗边。

首轮 Eevee 浅背景的 7、13、22、31、37、44 帧已实际读取：收紧可见，但连续弯带和截面亮纹仍像金属线圈。第二轮去掉绕截面的三条亮纹，改为沿路径向内加速的宽头、渐细尾能量团；截面随其鼓起，经过后变细。实际读取第二轮 22、31、37 帧，发现圆截面能量团又像蓝色珠子。因此第三轮将截面压成扫掠薄片，缩短主要卷曲弧，降低外层混白，保留小内核亮点。几何与着色使用同一原生阶段计算，不增加对象、粒子或 Python 播放逻辑。

## 原生编辑与预算

修改发生在用户载入的完整 Energy Charge 资产中，不是预览场景。仍为四层、四个显示对象、四个材质、12 个粒子槽；低质量总顶点上限 900，候选静态网格合计 894。核心占 438 个顶点；外侧流带从每条 49 行减到 41 行。宽的两条主路径各用 22 行采样，较细的四条各用 10 行，把同一预算优先用于主要轮廓。

Geometry Nodes 中的 `Compression Builds`、`Compression Amount`、`Pressure Height` 和 `Packets Accelerate Inward` 分别控制压缩窗口、横向收紧、高度和汇聚节奏。材质的 `Bright Intake Heads` 与 `Concentrated Inner Light` 分开控制流团和内核。侧栏保留实际使用的尺寸、时间、颜色、透明度、消蚀等控制。完整节点需使用 **Save Complete Effect** 保存，参数 JSON 仍只恢复基础模块。

微粒总旋转量由约 200° 降到约 92°，减少前半程切向绕行，让向内运动更明确。`Mote Intake Turn` 同时控制轨迹与朝向计算，手动修改后尖端仍跟随真实运动方向；侧栏 Size 从 0.055 调为 0.07，提高小图中的辨认度。没有增加数量、发射率或发光强度，抵达中心后仍停止。

实际读取 Eevee / AgX 浅背景双倍远景 13、31、42 帧后，发现亮色流团局部融入背景。最终材质增加由法线和视线计算的深蓝边界，`Core Edge Contrast` 可在材质节点中编辑，边界颜色跟随控制器。已用相同镜头重读这三帧：主路径边缘更完整，细小点缀仍弱。它不改变透明覆盖、几何或发光强度；不会据此宣称所有远景都达到成片要求。

默认核心保持不透明，通过 Geometry Nodes 删除消散区域的面；完全隐藏或塌缩后跳过其求值几何，避免透明层叠消耗 Cycles 穿透次数。Fade=0 保留消蚀前的面，但生命周期和整体塌缩仍生效。Opacity、Dissolve、Strength 的隐藏行为保持可测试。

普通 Shield、Ring、Emitter 和已有完整 `.blend` 不重建；旧节点、手动编辑和动画保留。没有提高发光强度，也没有外部纹理、缓存或帧处理器。

## 已验证与尚未验收

Blender 5.2.2 后台的 11 项入门资产测试通过，包含三轴压缩、900 顶点预算、参数隐藏、独立载入、时间控制及对用户数据的保护。新边界测试核对真实像素：覆盖不变、颜色变深，且跟随控制器换色。Fade 检查改用核心近景：原远景在收紧末段只覆盖十几个像素，无法可靠比较消蚀；第二轮几何探查也确认第 44 帧面数由 408 降为 288。这是采样修正，没有取消消散行为断言。

第三轮已读取 Cycles 暗背景的 7、13、17、21、25、29、33、37、41、45、49 帧，以及 Eevee 浅背景的 1、3、5……49 全部 25 张隔帧图。重分配路径采样并修改微粒后，又读取 Eevee 的 7、13、17、21、25、29、31、37、41、43、45、49 帧，以及 Cycles 侧面和俯视的 13、37 帧。外层由疏到密收紧，白色小内核保持焦点，45 帧仅余碎段，49 帧清空。相比同镜头 `15254ea` 的 Eevee 浅背景 22、37 帧，白色不再填满一整片外壳。扫掠带仍有平面感，细节与真实角色结合的表现尚未验证。

加入最终边界前，两引擎的 4、7、22、37、42、48 帧高清无插件重开逐通道一致。最终边界后，Cycles 这六帧、Eevee / AgX 浅背景远景的 13/31/42 帧和实际示例 ZIP 的三个资产再次通过原生检查；Eevee 远景三帧也逐通道一致，49 帧清空。实际发布的 0.22.2 充能资产和副本仍保留原圆形粒子。

最终源码 `7732e1a` 已生成 60 帧的 Eevee 浅背景连段，960×540、24 fps、2.5 秒。已实际读取 MP4 解码的 1、3、5……59 全部 30 张图，另读取源图 25–33 的连续相邻帧。充能 13–25 帧从较疏路径收紧到小焦点；28–30 帧白核退出、刀光接管亮部；31 帧命中时充能核心已清空。没有在这些抽查帧中看到明显焦点冲突，但这不是实时播放判断。刀光仍有规则宽片感，命中仍有花瓣形短闪、粗硬喷流和偏急的退场，后续优先处理。

该连段无插件重开后的 31/33 帧逐通道一致，60 帧无 VFX 几何。完整检查 ZIP 包含原生场景、MP4、60 张源 PNG、30 张解码图和校验记录，已构建成功；生成方式见 [连续检查包](CONTINUOUS_SKILL_REVIEW.md)。视频 SHA256 为 `9b157a9ea8e90c707f9a61da196218b66faee0cb0171a19a8d0d205636eace9a`，源设置与图片组合 SHA256 为 `d1fa1e8f2ffc695ce2a361693a45dad517b3bc5f9ae690a7ac0eb65432ce62c9`。它们标识本地检查批次；CI 独立生成自己的包。

在云端同一后台进程中，对基线与候选分别预热 48 帧，再测三轮共 144 个帧求值样本。`15254ea` 中位约 3.31 ms、95% 分位约 3.76 ms、最高 826 顶点；压缩候选约 4.21 / 5.67 ms、最高 894 顶点。这项测量在最终边界前进行；材质边界不改变几何图。测量不含绘制，也不是视口帧率或低配置硬件保证。

实际观看静态关键帧和解码抽帧不能证明实时播放观感。最终仍需在同镜头、同曝光下比较改动前后的暗/亮背景、多阶段和 Eevee；真实角色动作与低配置设备的视口帧率尚未验证。测试通过不表示艺术品质通过。
